Step 2d · Technical Note

The Gardner Timing-Error Detector

The interpolator can answer “what's the value at any μ.” The NCO decides “when, and which μ to ask for.” Neither one can tell you whether that choice is actually right. This is the piece that measures that.

What problem is this solving?

Picture the loop as it stands after sub-steps A and B: the NCO free-runs at a fixed nominal rate, telling the interpolator exactly when to evaluate and at what μ. If the transmitter's clock and the receiver's clock happened to match exactly forever, that would be the whole story. They don't — two independent oscillators always drift apart by some small amount, and even the STARTING offset between them is unknown. Left alone, the NCO's fixed guess drifts further from correct with every symbol.

What's missing is a way to look at the actual samples coming in and answer: “is the sampling instant we just used too early, too late, or about right?” That answer, as a single signed number, is exactly what the Gardner algorithm computes. A later piece (the loop filter, not yet built) will smooth that number and feed it back into the NCO's adj_in — closing the loop so the receiver keeps tracking the transmitter's true symbol rate indefinitely, not just at the one instant it happened to start correct.

Three samples, one number

Gardner's insight (Gardner, 1986) needs exactly three interpolated samples per symbol period, not one:

  • yon[n−1] — the on-time sample from the previous symbol.
  • ymid[n] — one extra sample taken exactly halfway between the previous symbol and this one — right where the signal is doing the most changing, if it's changing at all.
  • yon[n] — the on-time sample for the current symbol.
e[n] = ( y_on[n] − y_on[n−1] ) × y_mid[n]

Why this particular combination works: y_on[n] − y_on[n−1] is "how much the signal moved between the last two symbol decisions" — its sign says which way the signal is trending. y_mid[n] is a reading taken exactly at the symmetric midpoint between them. If the sampling grid is perfectly centered on the true symbol instants, that midpoint sits on an axis of symmetry — it doesn't systematically lean toward the earlier or the later symbol, so on average it doesn't correlate with which way the signal is trending, and the product averages to zero. If the whole sampling grid is shifted early or late, the midpoint reading gets consistently biased toward whichever neighbor it's now closer to — and that bias multiplies against the trend direction to produce a signed number that does not average to zero, with a sign that says which way to correct. Sanity check: 210000 × 45000 / 217 = 72097.78 — the hi/lo-split fixed-point result (72097) matches the floor of the exact floating-point value precisely, not just approximately. That's expected and worth being clear about: unlike the interpolator's RECIP6 constant (a genuine approximation of 1/6), splitting an operand into hi/lo halves before multiplying is an exact decomposition — y_mid = (mid_hi<<15) + mid_lo holds bit-for-bit. The only place any precision is actually discarded is the final, intentional >>>17 truncation.

This isn't just theory

The real RTL (gmsk_step2d_gardner_ted.v) implements exactly this — tag-dispatch, hi/lo split, two single-DSP48-safe multiplies, recombine, truncate. Its SIM gate checks two independent things: a bit-exact match against a Python mirror of this same fixed-point arithmetic across 183 real outputs (zero mismatches), and a genuine physical-meaning check using a synthetic alternating-symbol test signal at three timing offsets — average error came out exactly 0.0 when perfectly locked, and +461513 / −461514 when deliberately mistimed in each direction, symmetric and sign-flipped exactly as timing-recovery theory predicts. Both the Python reference model and the actual RTL simulation produced these same numbers independently.

Step 2a answers “what's the value at μ?” Step 2b decides when to ask and what μ to request. This page measures whether that request was actually right. All three are proven standalone now — next is the loop filter (Step 2e), the piece that turns this page's error number into the NCO's adj_in correction and finally closes the loop.
