Step 1 · Technical Note

Frequency Discriminator

The block every later RX stage depends on: turns raw IQ samples into an instantaneous-frequency signal that a bit slicer can threshold.

What problem this solves

GMSK is continuous-phase FSK under a Gaussian pre-filter — a 1-bit is one frequency, a 0-bit is another, and the phase never jumps discontinuously between them. That means the data isn't sitting in the amplitude or the raw phase of the received signal — it's sitting in how fast the phase is rotating from one sample to the next.

So demodulation is fundamentally an FM-radio problem: recover instantaneous frequency from the complex baseband stream coming off the AD9361's RX path (cf-ad9361-lpc). Every stage after this — bit slicing, timing recovery, preamble/sync detection — consumes this block's output, never the raw I/Q.

Two ways to compute it

The textbook definition is a derivative of phase: given the complex sample z[n] = I[n] + jQ[n], instantaneous phase is θ[n] = atan2(Q[n], I[n]), and instantaneous frequency is θ[n] − θ[n−1] (unwrapped). That's correct, but computing atan2 in fixed-point hardware means a CORDIC core — area and latency for a value we only need approximately.

ApproachHow it worksCost in fabric
Phase-difference (atan2) Compute absolute phase every sample via CORDIC, subtract previous sample's phase, unwrap. A CORDIC core (multi-cycle, iterative) plus unwrap logic. Exact, but heavier than this step needs.
Delay-and-conjugate-multiply Multiply each sample by the complex conjugate of the previous one: z[n]·z*[n−1]. The imaginary part of that product is proportional to sin(Δθ) — a direct stand-in for instantaneous frequency at small phase steps. One sample delay (a register) plus one complex multiply — 4 real multiplies and 2 adds. Fully combinational/pipelined, one sample per clock, no iteration.

Why the cross-product wins here

This is the standard “quadrature FM demodulator” trick used in real analog and digital radios — it trades a small-angle approximation for a massive reduction in logic. At our bit rate the phase step between samples is small, so the approximation error is negligible, and we get a block that's just multiplies and adds — no CORDIC, no iteration, one clock per sample.

Where it sits in the datapath

Input: complex IQ samples off the RX capture core, signed fixed-point (matching the AD9361's native word width). Output: one signed fixed-point discriminator value per input sample, same cadence. This block does not change the sample rate — that's still 2.304 Msps per the current RF params — it just re-expresses each sample as “how fast is phase moving right now” instead of I/Q.

Fixed-point notes

  • Bit growth from the multiply — multiplying two N-bit signed values needs 2N bits to avoid overflow; decide where to truncate/round before handing the result downstream, rather than growing width forever through the pipeline.
  • One register of delay is the entire “memory” this block needs — no filter taps, no state machine, just z[n−1] held one clock behind z[n].
  • Two expected output levels — per rf_params.h, MARK sits 150 kHz above the LO and SPACE sits 50 kHz above it. Those map to two known, separated discriminator output levels — that separation is exactly what Step 2's threshold will key off.

Test plan

This is exactly why the simplified TX frame matters: a continuous 1,0,1,0,1,0… pattern is a periodic square wave in the frequency domain — the cleanest possible input for this specific block, with no framing logic involved yet.

Pass condition

Capture the discriminator's output (ILA, or a register-peek in the same devmem style as Step 0) while the real TX frame is on air. It should toggle cleanly between two levels — one per bit — at the transmitted bit rate. Any noisy or single-level output means the multiply, delay, or Im{·} extraction has a bug, isolated entirely within this one block.
