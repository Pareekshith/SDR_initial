SDR_Link · RX Build Plan

The TX side is trivial. The RX side is the whole project.

TX transmits a fixed test frame once a second: an alternating bit pattern followed by a sync byte. Nothing adaptive, nothing to decode on that end — it's just a clean, repeatable signal to demodulate against. Everything hard lives on the ZedBoard's RX side, broken into seven gated steps so a failure at any point points at exactly one block.

Step 0 · Infrastructure proof

Done

gmsk_step0_regs.v

A trivial AXI4-Lite IP (ID / SCRATCH / COUNTER registers) proving the full toolchain — Verilog → packaging → block design → bitstream → JTAG → Linux readback — works end to end, with zero DSP in the way.

Test gatedevmem reads ID=0x474D534B, SCRATCH round-trips 0xDEADBEEF, COUNTER increments — all confirmed on hardware.

Step 1 · Frequency discriminator

In progress

IQ in → instantaneous frequency out

GMSK is continuous-phase FSK under a Gaussian filter — recovering data means recovering instantaneous frequency from the complex baseband stream. Every later stage consumes this block's output, never raw IQ.

Test gateFeed the real alternating-bit tone; discriminator output must toggle cleanly between two known levels, one per bit.

Step 2 · Bit slicer (fixed-rate)

Planned

discriminator out → naive bitstream

Threshold the discriminator output at a fixed sample offset — no timing recovery yet — just to prove an analog-ish signal can become a clean digital bit.

Test gateDecoded sequence matches 1010… most of the time, even if occasionally off from phase drift.

Step 3 · Symbol timing recovery

Planned

Gardner / Mueller timing loop

Replace the fixed-offset guess with a real loop that locks onto the actual symbol edges, tracking drift instead of hoping to get lucky on phase.

Test gateBit errors from Step 2 stabilize and disappear even as sample phase drifts over time.

Step 4 · Preamble correlator

Planned

bitstream → pattern match

Detect the 1010… run as a recognized pattern, distinct from simply receiving it — the first piece of real framing logic.

Test gateCorrelator output spikes only when the real preamble is present, stays low on noise.

Step 5 · Sync byte detector

Planned

0xD5 exact-match

Once the preamble is confirmed, look for the exact byte that marks “the frame starts now.”

Test gateLow false-lock rate on noise, reliable true detection on the real transmitted frame.

Step 6 · Frame state machine

Planned

IDLE → HUNT → LOCKED

Ties Steps 4 and 5 together into the thing that actually flags a valid frame arrival, gated on both preamble and sync agreeing.

Test gateReliable LOCKED transition once per second, matching the TX cadence exactly.
Given the frame carries no length/payload field, Step 6 is effectively the finish line for this phase — a repeatable once-a-second lock is the milestone, not arbitrary payload decoding.
