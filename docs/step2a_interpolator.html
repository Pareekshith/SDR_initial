Step 2a · Technical Note

Cubic Interpolation, Farrow Structure

How to compute the value of a signal at a moment in time that falls between two real ADC samples — the building block every symbol-timing-recovery loop is made of.

Why interpolate at all?

An ADC only ever hands you samples at fixed instants — one every 1/Fs seconds, locked to your receiver's clock. But the transmitter's symbol clock is a different physical oscillator, running at a very slightly different rate, with no fixed relationship to your sampling instants. The "best" moment to read each symbol — the middle of its eye, where the signal is cleanest — essentially never lines up exactly with a sample you actually have.

So a timing-recovery receiver needs to answer a question the ADC alone can't: "what would the signal have measured at some arbitrary moment between two samples I do have?" That's interpolation. Later, Gardner's algorithm (Step 3) will use the answer to that question, sample after sample, to figure out exactly where the true symbol centers are and keep tracking them as the transmitter's clock drifts. This page is only about the interpolation piece — how to answer the "what's the value at a fractional position" question at all — not yet about how the loop decides which position to ask for.

Lagrange interpolation, the idea

The simplest possible version: you have two points, and you want the value between them. If you just draw a straight line through them, that's linear interpolation — and it's already an example of the general idea: fit a curve through your known points, then read the curve's value wherever you like.

Lagrange interpolation is the direct extension of that idea: given N points, there is exactly one polynomial of degree N−1 that passes through all of them exactly. Two points → a line (degree 1). Four points → a cubic (degree 3). This project uses four points, giving a cubic — a good balance: enough points to bend and capture curvature (linear would just cut a straight chord across a curving signal), but not so many that a distant point still barely visible around outside our window pulls the fit around in ways low-order interpolation is better at avoiding.

The defining property

A degree-3 (cubic) interpolant built from 4 points passes through all four of them exactly. That's not a design choice to verify — it's what "interpolation" (as opposed to "curve fitting" / regression) means by definition. It's also the cleanest way to sanity-check an implementation: feed it points from a genuine cubic function, and the interpolated curve must reproduce that function exactly, with zero error, everywhere — not approximately. That's exactly how this project's implementation was first checked, before a single line of Verilog existed (see the worked example below).

Four points, one cubic curve

Label the four samples around the window we're interpolating within as x[−1], x[0], x[1], x[2] — sitting at integer positions −1, 0, 1, 2. We want the value at position μ, where μ is a fraction between 0 and 1 — μ=0 is exactly x[0], μ=1 is exactly x[1], and anything in between is genuinely "between the samples."

Lagrange's construction gives each of the four points its own weighting polynomial (its "basis function") that equals 1 at that point's own position and 0 at every other point's position. Add the four samples together, each multiplied by its own basis function evaluated at μ, and you get the interpolated value. Multiplying that all out and collecting terms by power of μ gives a clean, hardware-friendly form:

y(μ) = v0 + v1·μ + v2·μ² + v3·μ³
// four FIXED coefficients, computed once per window (mu doesn't appear yet):
v0 = x[0]
v1 = ( −2·x[−1] −3·x[0] +6·x[1] −x[2] ) / 6
v2 = ( x[−1] −2·x[0] +x[1] ) / 2
v3 = ( −x[−1] +3·x[0] −3·x[1] +x[2] ) / 6

Two quick checks that this is really doing what it claims: set μ=0 and everything except v0 vanishes, leaving y=x[0] exactly. Set μ=1 and the whole polynomial collapses to y=x[1] exactly (worth verifying by substitution if you want to see it, but it's a direct consequence of the basis functions each being 1 at their own point and 0 at the others). The curve is guaranteed to thread exactly through the two points it's interpolating between, using the outer two points only to shape the bend of the curve connecting them.

The Farrow structure: why this form is hardware-friendly

Writing the interpolant as a plain polynomial in μ (rather than directly summing four μ-dependent Lagrange basis functions) is the entire trick, and it has a name — the Farrow structure. The reason it matters: v0..v3 depend only on the four samples, never on μ. In a timing-recovery loop, μ changes almost every cycle (that's the whole point — it's the loop's own correction signal), while a fresh sample only arrives once per input clock. Separating "things that depend on the samples" from "the one thing that depends on the loop's current correction" means:

  • The expensive part (computing v0..v3) happens once per new sample — three sums and a couple of small constant divisions, not repeated for every possible μ you might ever ask for.
  • Evaluating at any particular μ is cheap — just three multiply-accumulates, using Horner's method to avoid computing μ²/μ³ separately: y = ((v3·μ + v2)·μ + v1)·μ + v0. Same answer as the polynomial above, just nested so each step is one multiply and one add.
  • The same hardware serves any μ — nothing about the circuit itself needs to change based on what fractional offset the timing loop currently wants; μ is just a number fed in.

Worked example, by hand

Using the demo's default numbers — x[−1]=1, x[0]=3, x[1]=4, x[2]=2 — and asking for the midpoint, μ=0.5:

StepComputationResult
v0x[0]3
v1(−2·1 −3·3 +6·4 −2) / 6 = 11/61.8333
v2(1 −2·3 +4) / 2 = −1/2−0.5
v3(−1 +3·3 −3·4 +2) / 6 = −2/6−0.3333
stage 1v3·μ + v2 = −0.3333×0.5 + (−0.5)−0.6667
stage 2(stage 1)·μ + v1 = −0.6667×0.5 + 1.83331.5
stage 3(stage 2)·μ + v0 = 1.5×0.5 + 33.75

Sanity check worth doing once: 3.75 sits between x[0]=3 and x[1]=4, as it must for any μ strictly between 0 and 1 — and it leans slightly toward 4, which matches the curve bending upward through that region given the neighboring points. Cross-checking the same numbers directly against the four Lagrange basis functions (rather than the v0..v3/Horner shortcut) gives the identical 3.75 — two independent routes to the same answer, which is exactly the kind of check worth doing before trusting either one.

This isn't just theory

The real RTL (gmsk_step2a_interpolator.v) implements exactly this — a 4-tap delay line feeding the v0..v3 computation, then three Horner multiply-accumulate stages, bit-for-bit the structure above. Before writing a line of Verilog, the coefficient formulas were checked in Python against a genuine cubic polynomial — interpolating a true cubic must reproduce it exactly, zero error, at any point, which is a much stronger check than "looks about right." The RTL itself was then validated against a sine-wave test signal (a sine has an exact, known value at any fractional position, so the test can check real sub-sample accuracy, not just "settles near the right level"), and passed with a worst-case deviation of about 0.2% — consistent with the small, expected gap between a cubic curve and a sine wave, not a sign of a bug.
